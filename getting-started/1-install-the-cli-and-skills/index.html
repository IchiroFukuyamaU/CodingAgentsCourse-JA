    1. CLI とスキルをインストールする¶

    このレッスンの進め方

    1. UiPath CLI をインストールしてサインインします。
    2. UiPath スキル をコーディングエージェントに追加します。
    3. エージェントが UiPath のタスクを認識することを確認します。

    ゴール¶

    このレッスンを終えると、動作する開発環境が手に入ります。uip CLI がインストール・認証済みで、UiPath スキルが追加され、エージェントが UiPath での構築方法を理解していることを簡単なチェックで確認できている状態です。これがほかのすべてのレッスンの土台になります。

    コーディングエージェントが「作り方」をどう変えるのか¶

    コーディングエージェントは、コードの書き方はすでに知っています。知らないのは UiPath のこと、つまり CLI コマンド、プロジェクト構造、プラットフォーム固有の作法です。それを埋めるのが次の 2 つです。

    • UiPath CLI は、エージェントがプラットフォームと会話するためのインターフェイスです。エージェントに UiPath を提供する方法として、コマンドラインインターフェイスが最もトークン効率の良い形だと分かってきました。
    • スキル は、その CLI を上手に使う方法をエージェントに教える仕組みです。タスクごとにコマンドの 手順 が記述されているため、コマンドを覚える代わりに「やりたいこと」を伝えるだけで済みます。

    覚えておく価値のある考え方が 1 つあります。「作ること」は仕事のごく一部にすぎない、ということです。エージェントは結果までの距離を一気に縮めてくれますが、その結果を本番で動かし続け、ガバナンスを効かせ、可観測性を保つのはプラットフォームの役割です。あなたは末端を作り、その下のインフラは UiPath が引き受けます。

    手順¶

    1. UiPath CLI をインストールする¶

    CLI をグローバルにインストールします。これで uip コマンドが使えるようになります。

    npm install -g @uipath/cli

    確認します。

    uip --version

    2. サインインする¶

    一度だけ認証します。コーディングエージェントはこのセッションを再利用するため、プラットフォーム上ではあなた自身として動作します。

    uip login --organization "<組織名>" --tenant "<テナント名>"

    <組織名> と <テナント名> は、ご自身の組織名・テナント名に置き換えてください。 Automation Cloud の画面右上、または URL（https://cloud.uipath.com/<組織名>/<テナント名>/...）から確認できます。

    ブラウザーが開くのでサインインしてください。

    ログインは自分のターミナルで実行してください

    uip login はブラウザーでの対話的なサインインが必要です。コーディングエージェントに実行させないでください。 ブラウザーが開いたまま応答がなくなることがあります。

    接続状態はいつでも確認できます。

    uip login status --output json

    3. UiPath スキルをインストールする¶

    uip skills install

    対話式のインストーラーが起動し、どのコーディングエージェント向けにインストールするかを選択できます。特定のエージェントを直接指定することもできます。

    uip skills install --agent claude

    これだけで完了します

    uip skills install を実行すると、スキルがローカル（~/.uipath/.skills）に展開され、コーディングエージェント側にもマーケットプレイスとプラグインが自動で登録されます。

    GitHub からマーケットプレイスを追加するといった追加の手順は必要ありません。

    インストールされたスキルを確認します。

    uip skills list

    一覧は変わります

    スキルは追加・統合されていきます。本文に固定の一覧は載せていません。実際に表示されたものを確認してください。

    本コースで使うのは uipath-agents / uipath-coded-apps / uipath-maestro-flow / uipath-rpa の 4 つです。

    4. ツールについて¶

    CLI の機能は「ツール」として拡張されます。uip or（Orchestrator）、uip codedagent、uip maestro などがそれにあたります。

    uip tools list --output table

    事前のインストールは不要です

    一覧に出ていないツールでも、初めて使うときに自動でインストールされます。 手動での導入作業は要りません。

    ただし初回は数分かかることがあります。 コマンドが返ってこなくても、しばらく待ってください。

    最新に保つには次を実行します。

    uip tools update
uip skills update

    5. セットアップを確認する¶

    新しいスキルを読み込んだ状態でコーディングエージェントを起動し、コマンドではなく「やりたいこと」を伝えてみましょう。

    使える UiPath のスキルを教えてください。また、いま接続している環境の中にあるテナントを一覧表示できますか？

    正しくセットアップされていれば、エージェントは uip コマンドを提案・実行して答えを返してくれます。

    UiPath のタスクを認識しない場合は、コーディングエージェントを再起動してプラグインを読み込み直してください。

    セッション・アイデンティティ・セキュリティ

    エージェントはあなたのセッションを引き継ぎ、あなたの権限で動作します。 共有アカウントやサービスアカウントとして動かしたい場合は、個人ログインではなく External Application セッションでサインインしてください。

    エージェントによっては、コマンドを隔離された環境（サンドボックス）で実行するものがあります。その場合、uip をあなたの権限で実行できないことがあります。ターミナルでは uip login status が接続済みと表示されるのに、エージェント側は未接続だと言う場合は、次のように伝えてください。

    UiPath CLI を使うときは、権限を昇格させた実行を優先してください。サンドボックス内で実行されたコマンドは、
私の実際のターミナルセッションを反映していない可能性があります。

    uip 全体を一括で許可しないでください

    コーディングエージェントが「uip コマンドをすべて許可しますか？」と尋ねてきても、一括承認は避けてください。 削除系の破壊的なコマンドまで含まれてしまいます。

    uip or folders list のような読み取り・一覧表示系のプレフィックスを、必要になった都度承認していくほうが安全です。本コースでも、削除を伴う操作は片付けだけです。

    このレッスンでできたこと¶

    • uip CLI をインストールし、演習環境にサインインした
    • UiPath スキルをコーディングエージェントに追加した
    • エージェントが UiPath のタスクを認識することを確認した
